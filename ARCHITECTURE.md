# Architecture

## 1. High-Level Overview

This repository is a **static website** for a Russian-language knowledge base ("TokenBel Wiki"), not a service or application. The primary deliverable is a static `public/` directory generated by Hugo and served verbatim by a Cloudflare Worker configured with Static Assets. There is no Worker script, no KV namespace, no bindings, and no origin server (`wrangler.toml`, `docs/deployment.md`).

The core is a classic static-site-generator pipeline. Markdown content in `content/` is combined with local Hugo templates in `layouts/` and a standalone Tailwind CSS 4 source (`static/css/input.css`) under the configuration in `hugo.yaml`, producing a self-contained set of HTML/CSS/asset files. All presentation logic is local — there is no external Hugo theme and no Sass/SCSS dependency, which is why the Hugo **standard** edition is intentionally used instead of Extended (`docs/deployment.md`).

A second, independent toolchain coexists alongside the site build. `tools/wiki-media/` is an isolated Python 3.11+ CLI (own `uv`/`pyproject.toml`, `boto3`/`Pillow`) that publishes new images from a gitignored `.wiki-media/inbox/` to immutable Cloudflare R2 objects and rewrites `upload:` markers in `content/` to `cdn-wiki.tokenbel.info` CDN URLs. It never participates in the Hugo build and never performs a Git commit (`tools/wiki-media/AGENTS.md`).

Two site-build entrypoints target different environments. Local development and validation run Hugo inside `hugomods/hugo:0.164.0` via the `Makefile`; Cloudflare production builds run `build.sh`, which downloads pinned Hugo and Node binaries, verifies SHA-256 checksums, and is restricted to Linux x86_64 (`build.sh`, `Makefile`). The runtime model is request-to-static-asset: an incoming request is resolved against the deployed `public/`, and unmatched paths fall back to the nearest `404.html` with HTTP 404 (`wrangler.toml` `not_found_handling = "404-page"`).

Evidence anchors: `hugo.yaml`, `wrangler.toml`, `build.sh`, `Makefile`, `layouts/`, `tools/wiki-media/pyproject.toml`, `docs/deployment.md`.

## 2. System Architecture (Logical)

### Content Layer

- Responsibility: Authoring surface — Markdown articles and section landing pages, plus front matter that drives navigation, dates, and SEO.
- Code locations: `content/`, `archetypes/default.md`.
- Entry points: `content/_index.md` (home), `content/<section>/_index.md` (section landing), `content/<section>/<slug>/index.md` (leaf-bundle article).
- Depends on: Site Configuration (consumes `menus.main`, `params`, locale).
- Must not depend on: Templates or CSS directly; the contract is data-only via front matter.
- Owns: Page titles, descriptions, `weight`, `date`/`lastmod`, and the home `heroPrimary*` / `heroSecondary*` parameters consumed by `layouts/home.html`.
- State and external boundaries: `enableGitInfo: false` (`hugo.yaml`) → dates come exclusively from front matter, never Git. New images are not stored here; they enter via the Media Publishing Toolchain as `upload:` markers.
- Evidence: `content/AGENTS.md`, `content/_index.md`, `layouts/home.html`, `hugo.yaml`.

### Presentation Layer

- Responsibility: All HTML structure, SEO meta, and styling. Pure presentation — no business logic.
- Code locations: `layouts/` (`_default/baseof.html`, `_default/list.html`, `_default/single.html`, `_markup/render-table.html`, `home.html`, `404.html`, `partials/*`), `static/css/input.css`.
- Entry points: `layouts/_default/baseof.html` (page skeleton), `layouts/partials/head.html` (title, canonical, robots, OG, JSON-LD), `layouts/home.html` (home composition).
- Depends on: Content Layer front matter (reads `.Params.heroPrimary*` / `heroSecondary*`, `excludeFromRecent`), Site Configuration (`site.Params.*`, `site.BaseURL`).
- Must not depend on: External Hugo themes, Dart Sass / `.scss`, JavaScript frameworks (`layouts/AGENTS.md`, `docs/deployment.md`).
- Owns: Canonical URL emission, `noindex,follow` for 404, OpenGraph/JSON-LD, and the static CSS link.
- State and external boundaries: pinned `@tailwindcss/cli` (`package.json` `css:build`) compiles two committed outputs — `static/css/output.css` and `static/css/tailwind.min.css`. `layouts/partials/css.html` links **only** `tailwind.min.css` (hardcoded, no environment switch). Inferred: `output.css` is retained as a `css:watch`/freshness reference and is not referenced by any template.
- Evidence: `layouts/AGENTS.md`, `layouts/partials/css.html`, `layouts/partials/head.html`, `package.json`.

### Media Publishing Toolchain

- Responsibility: Authoring-time publishing of new images to immutable Cloudflare R2 and atomic rewriting of `upload:` markers in `content/` to CDN URLs. The only component that mutates `content/` outside manual editing and the only one that touches R2/CDN.
- Code locations: `tools/wiki-media/` (`pyproject.toml`, `uv.lock`, `Makefile`, `src/wiki_media/`).
- Entry points: `wiki_media.cli:main` (console script `wiki-media` / `python -m wiki_media`), commands `publish|validate|cleanup`; wrapped by root `make media-*` targets.
- Depends on: Content Layer (`content/` Markdown is scanned for `upload:` markers and rewritten in place), the gitignored inbox `.wiki-media/inbox/`. External: Cloudflare R2 (S3-compatible API) and `https://cdn-wiki.tokenbel.info`.
- Must not depend on: Hugo, Node, Docker, or the site build toolchain — separate Python 3.11+ runtime under `uv` (`tools/wiki-media/AGENTS.md`).
- Owns: The content-addressed R2 object-key scheme (`wiki/media/images/<sha[:2]>/<sha><ext>`), the bucket/prefix/CDN triple, and the atomic transaction with rollback backups in `.wiki-media/run/`.
- State and external boundaries: `publish` uploads immutable objects (no overwrite of mismatched content, no deletes, SHA-256 verified in `r2.py`), then atomically stages and promotes Markdown rewrites via `transaction.py`. `--dry-run` / `validate` without `--remote` make no network calls and need no credentials.
- Evidence: `tools/wiki-media/AGENTS.md`, `tools/wiki-media/README.md`, `tools/wiki-media/src/wiki_media/publisher.py`, `config.py`, `r2.py`, `transaction.py`, `keys.py`.

### Site Build Toolchain

- Responsibility: Reproducible generation of `public/` from the Content, Presentation, and Configuration layers. Two alternative front-ends for two environments.
- Code locations: `Makefile` (Docker/local path and CSS regeneration), `build.sh` (pinned Cloudflare path), `package.json` (Tailwind CLI and Wrangler scripts).
- Entry points: `make css-build` / `make dev` / `make build` / `make check` (Docker, `hugomods/hugo:0.164.0`); `./build.sh` (native pinned Hugo 0.164.0 + Node 24.18.1, Linux x86_64 only); `make cloudflare-build` / `make deploy` wrap the package scripts.
- Depends on: Content, Presentation, Site Configuration layers (consumes them as Hugo inputs).
- Must not depend on: The Media Publishing Toolchain — Hugo never invokes `wiki-media`; media is already rewritten into `content/` before any build. Extended Hugo features and unpinned tools are disallowed (`build.sh` pins and checksum-verifies all binaries).
- Owns: The `public/` artifact, `resources/`, `.cache/` (all build outputs, git-ignored per `.gitignore`).
- Evidence: `Makefile`, `build.sh`, `package.json`, `.gitignore`.

### Site Configuration & Static Assets

- Responsibility: Global site identity, navigation, external link catalog, and immutable files served as-is.
- Code locations: `hugo.yaml`, `static/` (`favicon.svg`, `wiki_logo.*`, `css/`).
- Entry points: `hugo.yaml` (`baseURL`, `languages.ru`, `taxonomies`, `menus.main`, `params.*`).
- Depends on: Nothing (root configuration).
- Owns: Canonical domain `https://wiki.tokenbel.info/`, section menu order, dashboard/tokens/market external URLs.
- Evidence: `hugo.yaml`, `static/`.

### Cloudflare Deployment Target

- Responsibility: Deliver the built `public/` as a Worker with Static Assets. Configuration-only — no code.
- Code locations: `wrangler.toml`, `docs/deployment.md`.
- Entry points: `wrangler deploy` (`npm run deploy`, orchestrated by `build.sh` + `npm run deploy` in Workers Builds).
- Depends on: Site Build Toolchain output (`public/`, via `[assets] directory = "./public"`).
- Owns: Worker name `tokenbel-wiki`, `not_found_handling`, routes, observability logs/traces, smart placement.
- Evidence: `wrangler.toml`, `docs/deployment.md`.

### Dependency direction

```text
  tools/wiki-media (Python/uv) ──► Cloudflare R2 ──► cdn-wiki.tokenbel.info
   ▲   │  (authoring-time: rewrites upload: → CDN URLs in content/)        │
   │   └──────────► content/  (mutates Markdown; never git-commits)       │
 inbox                                                                     │
   │                                                                       │
hugo.yaml ──┐                                                              │ CDN URLs referenced
content/ ───┼──► Hugo (standard ed.) ──► public/ ──► Wrangler ──► Cloudflare Worker (static assets)
layouts/ ───┤        ▲                       │
static/  ───┘        │                       └─► 404.html fallback (HTTP 404)
       CSS: @tailwindcss/cli → committed static output (only tailwind.min.css is linked)
```

The Hugo pipeline runs strictly left-to-right; build output never feeds back into sources. The Media Publishing Toolchain is a separate authoring-time side path into `content/` and R2; it is not chained into the Hugo build.

## 3. Code Map (Physical)

```text
content/            Markdown + front matter; auto-assembled sections (news, statistics, guides, policies, about)
archetypes/         `hugo new` template (`default.md`)
layouts/            Local Hugo templates only — no theme
  _default/         baseof.html (skeleton), list.html (section), single.html (article)
  _markup/          render-table.html (Markdown table render hook)
  partials/         head.html (SEO + canonical/robots), css.html (links tailwind.min.css), header/footer, page-dates, recent-pages (excludeFromRecent), section-card
  home.html         home composition (hero + site.Sections + recent + useful links)
  404.html          fixed 404 copy and actions
static/css/         input.css source; output.css and tailwind.min.css committed CLI output
static/             immutable files served verbatim (CSS, favicon.svg, wiki_logo.*)
hugo.yaml           site config: baseURL, ru locale, menus, params, taxonomies
tools/wiki-media/   isolated Python CLI: publish/validate/cleanup → immutable R2 + CDN (own uv/Ruff/pytest)
  src/wiki_media/   cli, publisher, r2, transaction, keys, config, discovery, images, markdown, models, reporting
Makefile            Docker-based local dev/build/check + media-* wrappers
build.sh            pinned Cloudflare build (Linux x86_64, checksum-verified Hugo+Node)
package.json        Tailwind CLI and Wrangler scripts
wrangler.toml       Cloudflare Worker Static Assets config
docs/deployment.md  deployment, staging, rollback, pinned-tool rationale
```

Generated/build areas excluded from the model: `public/`, `resources/`, `.cache/`, `.wrangler/`, `node_modules/`, `.hugo_build.lock`, `tools/wiki-media/.venv/`, `.wiki-media/` (all git-ignored by `.gitignore`). `assets/` and `scripts/` are reserved and empty.

## 4. Life of a Request / Primary Data Flow

### Build flow — sources to static site

1. Trigger: `make build` (local) or `./build.sh` (Cloudflare).
2. Entry point: Hugo CLI inside Docker (`Makefile`) or the pinned native binary (`build.sh`).
3. Coordination: Hugo reads `hugo.yaml`, discovers `content/` sections, resolves templates from `layouts/`.
4. Core or domain processing: Markdown rendered to HTML; `site.Sections.ByWeight` drives home/section lists; `.RegularPages.ByLastmod.Reverse` orders article lists; `recent-pages.html` filters out pages with `excludeFromRecent`; `css.html` links the committed `tailwind.min.css`.
5. Persistence or external interaction: Files written to `public/` (`--gc --minify --environment production`); no network calls during build.
6. Output or side effect: Self-contained `public/` directory with `tailwind.min.css` and a root `404.html`.

Architectural boundaries crossed:
- Content front matter → template rendering (data contract only).
- `static/css/input.css` → pinned Tailwind CLI → committed `static/css/tailwind.min.css` → Hugo static copy.

Evidence:
- `Makefile`, `build.sh`, `layouts/partials/head.html`, `layouts/home.html`, `layouts/_default/list.html`, `layouts/partials/recent-pages.html`.

### Media publish flow — inbox images to immutable R2 + CDN

1. Trigger: `make media-publish MEDIA_PATH=...` or `python -m wiki_media publish <path>`.
2. Entry point: `wiki_media.cli:main` → `publisher.publish`.
3. Coordination: `find_repository_root` anchors on `.git` + `hugo.yaml` + `content/`; `discovery.py` resolves scope (whole `content/`, a subtree, or one `index.md`); Markdown is scanned for `upload:` image markers.
4. Core or domain processing: `images.py` validates each `.wiki-media/inbox/` image (format, size, SHA-256); `keys.py` derives the content-addressed R2 object key; `validate` blocks forbidden published URLs (non-CDN hosts, `r2.dev`, `static.tokenbel.info`, disallowed prefixes).
5. Persistence or external interaction: `r2.publish_assets` uploads only missing objects to bucket `tokenbel-wiki` and verifies remote SHA-256 metadata; mismatched existing objects are never overwritten, objects are never deleted.
6. Output or side effect: `transaction.py` stages Markdown rewrites and atomically promotes them into `content/` with rollback backups under `.wiki-media/run/`; no Git commit is performed. Resulting `https://cdn-wiki.tokenbel.info/wiki/media/images/...` URLs are then ordinary references consumed by the next Hugo build.

Architectural boundaries crossed:
- `content/` Markdown ↔ external R2/CDN (the only source path that leaves the repo).
- Separate Python/uv runtime, fully outside the Hugo/Node build.

Evidence:
- `tools/wiki-media/src/wiki_media/publisher.py`, `r2.py`, `transaction.py`, `keys.py`, `config.py`, `tools/wiki-media/AGENTS.md`.

### Request flow — runtime serving at Cloudflare

1. Trigger: HTTP request to the Worker hostname.
2. Entry point: Cloudflare Worker with Static Assets, asset root `./public` (`wrangler.toml`).
3. Coordination: Cloudflare resolves the path against the deployed static files.
4. Core or domain processing: None — pure static asset match; no Worker script executes.
5. Persistence or external interaction: None at runtime.
6. Output or side effect: Matched file (200) or nearest `404.html` with HTTP 404 (`not_found_handling = "404-page"`); canonical `<link>` always points at `https://wiki.tokenbel.info/`.

Architectural boundaries crossed:
- Build artifact (`public/`) → edge runtime (immutable handoff).

Evidence:
- `wrangler.toml`, `layouts/partials/head.html`, `docs/deployment.md`.

## 5. Architectural Invariants & Constraints

- Rule: No external Hugo theme and no Dart Sass / `.scss`; Tailwind CSS 4 uses a single plain-CSS source.
- Rationale: Keeps the Hugo **standard** edition while preserving a reproducible CSS build.
- Enforcement / Signals: `layouts/AGENTS.md`, `package.json`; absence of `theme`/`themes/` and `.scss` files; `make css-build` regenerates committed static output and `make check` detects stale CSS by diffing both committed files against fresh CLI builds.

- Rule: Page dates come from front matter, never Git.
- Rationale: Decouples rendered dates from commit history.
- Enforcement / Signals: `enableGitInfo: false` in `hugo.yaml`; `.Lastmod` resolved from front matter in `layouts/partials/page-dates.html`.

- Rule: The canonical domain is fixed at `https://wiki.tokenbel.info/`.
- Rationale: SEO consistency across local, staging, and production.
- Enforcement / Signals: `baseURL` in `hugo.yaml` and matching `wiki.tokenbel.info` routes in `wrangler.toml`; `.Permalink` canonical/OG emission in `layouts/partials/head.html`; `layouts/AGENTS.md` prohibits `localhost`/port in canonical.

- Rule: The 404 page must emit `noindex, follow` and the literal text `Страница не найдена`; the home must contain `База знаний TokenBel`.
- Rationale: Required SEO/copy contracts enforced by CI-equivalent validation.
- Enforcement / Signals: `make check` greps `public/index.html` and `public/404.html`; `layouts/404.html`, `layouts/partials/head.html`, `content/_index.md`.

- Rule: Sections are auto-assembled from `content/`; menu order is declared in `hugo.yaml`.
- Rationale: Single source of truth for navigation.
- Enforcement / Signals: `home.html` and `_default/list.html` iterate `.Sections.ByWeight`; `menus.main` in `hugo.yaml`.

- Rule: The deployed unit is static only — no Worker script, bindings, or KV; `public/` is its sole input.
- Rationale: Operational simplicity and zero runtime cost.
- Enforcement / Signals: `wrangler.toml` has no `main`, bindings, or secrets and sets `[assets] directory = "./public"`; `.gitignore` excludes `public/`, `resources/`, `.cache/`, `.wrangler/`.

- Rule: Cloudflare builds use pinned, checksum-verified tooling and run only on Linux x86_64.
- Rationale: Reproducible production builds.
- Enforcement / Signals: `build.sh` (`require_linux_x64`, SHA-256 checks, pinned Hugo 0.164.0 / Node 24.18.1 / Wrangler 4.118.0 via `package.json`); `docs/deployment.md`.

- Rule: R2 media objects are content-addressed and immutable — never overwrite mismatched content, never delete, always verify remote SHA-256.
- Rationale: Deduplication, durability, and safe re-publishing of Markdown.
- Enforcement / Signals: `tools/wiki-media/src/wiki_media/r2.py` (`_head`/`_matches`, refuses mismatched overwrite), `keys.py` (content-addressed key), `tools/wiki-media/AGENTS.md`. Inferred: enforcement is in-code; no cross-tool validator exercises it.

- Rule: `upload:` markers are strictly inbox-relative (`.wiki-media/inbox/`); network-free paths (`publish --dry-run` without `--remote`, `validate` without `--remote`) require no credentials.
- Rationale: Safe, local-first media authoring.
- Enforcement / Signals: `config.py` (`MEDIA_INBOX_ROOT`), `images.py` (`resolve_inbox_path` rejects absolute/`..`/`~`/URI/symlink), `publisher.py` (credentials only touched on remote paths).

- Rule: The Media Publishing Toolchain runs in a separate Python/uv runtime and never performs a Git commit.
- Rationale: Isolates an external-credentialed, repo-mutating tool from the static build.
- Enforcement / Signals: `tools/wiki-media/pyproject.toml` (own deps, `requires-python >=3.11`), `tools/wiki-media/Makefile` (`uv sync`/`uv run`), `tools/wiki-media/AGENTS.md`; `.gitignore` excludes `.wiki-media/`.

## 6. Documentation Strategy

This `ARCHITECTURE.md` owns the global architecture map: layers, dependency direction, representative build/runtime/media flows, and architectural invariants. It does not duplicate task-specific operating rules.

- `/AGENTS.md` — repository-wide agent operating rules and task-based context routing (referenced, not copied here).
- `content/AGENTS.md` — local rules for editing `content/` and the front-matter/`upload:` contracts.
- `layouts/AGENTS.md` — local rules for templates, SEO meta, and the CSS pipeline.
- `tools/wiki-media/AGENTS.md` — local rules for the media CLI: boundaries, R2-immutable contract, safe-change rules.
- `tools/wiki-media/README.md` — canonical `wiki-media` commands, `upload:` authoring syntax, R2 credentials, and rollback.
- `docs/deployment.md` — authoritative deployment runbook: pinned tools, Workers Builds setup, staging, cutover, rollback.
- `README.md` — project overview, local-run requirements, and contributor structure guide.

No ADRs, package READMEs (besides the tool above), schema docs, or `DESIGN.md` exist in the repository; their absence does not limit architecture understanding because the site is configuration- and template-driven with no API surface or code modules to document.
