# Форматы входного дайджеста

Сначала определите формат, затем извлеките **период**, **рабочее название** и **список
фактов**. Новость пишется только по списку фактов.

## A. Черновик `generate-digest` из `../tbel` (`wiki/digest/<FROM>-<TO>.md`)

Признаки: front matter с `date_from`, `date_to`, `digest_title`, `tags: digest` (или уже
Hugo-поля из `../tbel/wiki/digest/template.md`), H1 `# <Название>`, разделы как в
новости.

- Период: `date_from` / `date_to`; иначе из имени файла `YYYY-MM-DD-YYYY-MM-DD.md`.
- Название: `digest_title` или `seoTitle` — кандидат, а не догма.
- Факты: каждое предложение «Главного» и каждый пункт списков.
- Рядом может лежать лист фактов `../tbel/.local/digest/<FROM>-<TO>.facts.md` — если есть,
  читайте его тоже: там точные метки («Где») и оговорки («Доступно?»), которых в
  черновике нет. Колонка «Коммиты» — только для проверки, в текст не идёт.
- `<!-- скриншот: … -->` — подсказки для картинок, в файл не переносятся.

## B. Лист фактов (`*.facts.md`)

Признаки: таблица `| Тема | Что изменилось для читателя | Где | Раньше → теперь | Коммиты | Доступно? | Куда |`
и раздел «Сознательно выкинуто».

- Период: из заголовка («дайджест 2026-10-15 — 2026-11-17») или имени файла.
- Факты: строки с `Куда` ≠ `—`. Колонка `Куда` — подсказка раздела.
- «Сознательно выкинуто» не пересматривайте без явной просьбы.

## C. Готовая новость старого формата или Hugo-черновик

Признаки: Hugo front matter (`title`, `description`, `date`), разделы с эмодзи или
`####`.

- Задача — переписать в текущий формат, сохранив факты. Если файл уже лежит в
  `content/news/`, правьте его на месте и **не меняйте slug** (ссылки уже опубликованы).
- Период: из title «(DD.MM.YYYY - DD.MM.YYYY)», иначе `date`.

## D. Свободный текст: чейнджлог, release notes, пост в Telegram, список коммитов

- Период: из текста; не нашли — спросите пользователя (по умолчанию предложите: от дня
  после `date` последней новости до сегодняшнего дня).
- Сначала составьте рабочий список фактов в сессии (не в репозитории) по колонкам листа
  фактов B: тема, что изменилось для читателя, где, раньше → теперь, доступно?, куда.
- Сырые коммиты (`feat:`, `fix:`, хеши) — это не дайджест. Переводите их в изменения для
  читателя; внутренние (`refactor`, `chore`, `test`, `deps`, `ci`) выкидывайте.

## Определение периода и дат

| Где нашли                                   | FROM          | TO            |
| ------------------------------------------- | ------------- | ------------- |
| `date_from` / `date_to`                     | `date_from`   | `date_to`     |
| имя файла `2026-10-15-2026-11-17.md`        | первая дата   | вторая дата   |
| «(15.10.2026 - 17.11.2026)» в заголовке     | первая дата   | вторая дата   |
| одна дата                                   | —             | эта дата      |

`date` = `lastmod` = TO. Даты вне форматов — переведите в ISO; при неоднозначности
(`03.04` без года) спросите.

## Проверка перекрытия

Перед записью сравните период с `date` существующих новостей:

```bash
grep -H '^date:' content/news/*/index.md | sort -t'"' -k2 | tail -5
```

Если период пересекается с уже опубликованной новостью или каталог slug уже существует —
остановитесь и спросите: обновить существующую, сузить период или всё же создать новую.
