# Новость TokenBel из дайджеста

**Вход:** путь к Markdown-файлу дайджеста. Необязательно: картинки (файлы в
`.wiki-media/inbox/news/`), «Вехи» (событие проекта), желаемый заголовок.

**Выход:** один файл `content/news/<slug>/index.md` в текущем формате новостей (эталон —
`content/news/portfeli-i-obligacii-15102026-17112026/index.md`). Больше ничего в
репозитории не создаётся и не коммитится. Входной файл и соседние репозитории
(`../tbel`, `../tokenbel-workers`) — только чтение.

Это не перенос текста, а редактура: дайджест — сырьё. В новость попадает только то, что
читатель увидит, словами читателя, с точными метками интерфейса, оговорками и ссылками на
руководства. Факты не придумываются: каждое утверждение опирается на вход.

## Справочники

Перед письмом прочитайте (пути относительно папки скилла):

- `references/input-formats.md` — как распознать формат входа, период и факты.
- `references/style.md` — читатель, голос, формула, разделы, метаданные, ссылки, картинки.
- `references/examples.md` — что редактор меняет в черновике; старый и новый формат.
- `references/glossary.md` — канцелярит, жаргон, написание названий (их проверяет валидатор).
- `references/guides-map.md` — на какие руководства ссылаться.
- `references/template.md` — каркас файла.

## Порядок работы

Скопируйте чек-лист и отмечайте шаги:

```text
- [ ] 1. Разобрать вход: формат, период, факты
- [ ] 2. Проверить перекрытие с опубликованными новостями
- [ ] 3. Отобрать факты и разложить по разделам
- [ ] 4. Уточнить метки интерфейса и ссылки
- [ ] 5. Выбрать заголовок, теги, slug
- [ ] 6. Написать и сохранить новость
- [ ] 7. Картинки
- [ ] 8. Валидатор и сборка
- [ ] 9. Перечитать как редактор
```

### 1. Разобрать вход

Прочитайте файл целиком (большой — частями). По `input-formats.md` определите формат
(A–D), период `FROM`–`TO` и выпишите в сессии список фактов: тема, что изменилось для
читателя, где, раньше → теперь, условия доступа, раздел. Для формата A загляните в лист
фактов `../tbel/.local/digest/<FROM>-<TO>.facts.md`, если он есть. Период не
определяется — спросите пользователя.

### 2. Проверить перекрытие

```bash
grep -H '^date:' content/news/*/index.md | sort -t'"' -k2 | tail -5
```

Период пересекается с опубликованной новостью или каталог slug уже есть — остановитесь и
спросите. Существующую новость правьте на месте без смены slug.

### 3. Отобрать факты

По «Что выкидывать» в `style.md` вычеркните внутреннее, промежуточное, недоказанное.
1–2 темы с самым заметным эффектом — в «Главное», остальное — в группы «Что стало
удобнее», ошибки, которые видел пользователь, — в «Исправили», до 3 ощутимых пунктов — в
«Технически», открытый API и MCP — в «Для AI-агентов и разработчиков». Запомните, что
выкинули и почему, — это пойдёт в ответ.

### 4. Уточнить метки интерфейса и ссылки

Метки в дайджесте часто пересказаны («переключатель на круговую»). Если рядом есть
`../tbel`, найдите точную надпись в шаблонах и JS (только чтение):

```bash
grep -rn "Круговая" ../tbel/src/tbel/templates ../tbel/src/tbel/static/js | head
```

Найдена — пишите её дословно в «ёлочках» (кнопки — жирным). Не найдена — оставьте
формулировку дайджеста без кавычек, не выдумывайте. Так же уточняйте условия доступа
(«для авторизованных»). Для каждой темы подберите руководство по `guides-map.md` и
проверьте, что страница существует.

### 5. Заголовок, теги, slug

- `seoTitle` — 2–5 слов о 1–2 главных темах; `title` = `seoTitle`.
- `description` — «Дайджест TokenBel за <период словами>: <2–4 темы>.», 100–220 символов.
- `date` = `lastmod` = `TO`.
- Теги — из существующих:

  ```bash
  grep -h '^  - ' content/news/*/index.md | sort | uniq -c | sort -rn
  ```

- Slug:

  ```bash
  S=.agents/skills/digest-to-news/scripts
  python3 $S/slug.py "<seoTitle>" <TO> --from <FROM>
  ```

### 6. Написать и сохранить

Заполните `references/template.md` по `style.md` и сохраните в
`content/news/<slug>/index.md`. Пустые разделы и подгруппы удалите вместе с их `---`.
«Вехи» — только из входа или со слов пользователя. Готовые CDN-картинки из входа
переносите как есть.

### 7. Картинки

- Если пользователь дал файлы или в `.wiki-media/inbox/news/` есть подходящие по имени
  снимки, вставьте marker `![<подпись>](upload:news/<file>.png)` сразу после абзаца темы
  (не больше трёх в «Главном»). Подходит ли снимок — посмотрите на него, прежде чем
  вставлять.
- Проверьте план загрузки без записи:

  ```bash
  make media-publish-dry-run MEDIA_PATH=content/news/<slug>
  ```

- Реальная загрузка в R2 (`make media-publish MEDIA_PATH=content/news/<slug>`) — только
  по явной просьбе пользователя: нужны credentials, объекты неизменяемы.
- Картинок нет — HTML-комментариев не оставляйте (они утекают в публичный `index.md`);
  что снять, перечислите в ответе.

### 8. Валидатор и сборка

```bash
python3 $S/check_news.py content/news/<slug>/index.md
```

Исправьте все `ERROR`. Каждый `WARN` исправьте или оставьте осознанно (например,
неопубликованный `upload:` marker). Повторяйте, пока ошибок нет. Затем соберите сайт:

```bash
make check          # Docker; проверяет CSS, HTML и парность index.md
```

Docker недоступен — сообщите об этом в ответе, не запускайте `build.sh`.

### 9. Перечитать как редактор

Валидатор не оценивает смысл. Прочитайте текст глазами инвестора:

- Понятно ли из каждого пункта, где это найти и что с этим делать?
- Есть ли утверждение или эффект, которого нет во входе? Удалите.
- Не начинаются ли соседние предложения одинаково, не повторяется ли мысль?
- Можно ли выкинуть ещё один слабый пункт? Если да — выкиньте.
- 330–840 слов?

## Ответ пользователю

Коротко: путь к файлу, `seoTitle`, 2–3 главные темы, что сознательно не вошло и почему,
какие метки не удалось подтвердить, итог валидатора и `make check`, что снять на
скриншоты (если картинок нет), вопросы к редактору (нужны ли «Вехи», нужна ли загрузка
картинок). Текст новости целиком в ответ не вставляйте. Не коммитьте и не деплойте.
